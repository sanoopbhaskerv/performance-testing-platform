Other traps, all real, all hit at least once:

- Bash working directory **persists between calls**. `cd` into `platform-ui` breaks later commands.
  Always `cd` to the repo root or use absolute paths.
- Single test across the reactor needs `-Dsurefire.failIfNoSpecifiedTests=false`.
- `platform-ui/src/App.css` is **imported by nothing** — `main.tsx` loads only `index.css`.
  Rules added to App.css silently do nothing.
- **No load is generated by default.** The `fake` provider produces synthetic results. Real load
  needs `brew install jmeter` and
  `--platform.orchestration.execution-provider=local-jmeter`. Never present a `fake` run's numbers
  as evidence a system performs.

## 2. First task: reports

**None of this exists today.** Confirmed by grep: no report endpoint, no report UI, no artifact
download. `GET /api/v2/test-runs/{runId}/artifacts` returns *references only* — key, digest, size —
and deliberately no URL.

The data is all there and already stored. Nothing new needs measuring.

### 2a. Artifact download (build first — the report links to it)

`GET /api/v2/test-runs/{runId}/artifacts/{artifactId}/content`

- Authorize per request via `ReadTestRunUseCase` (it already does the team check).
- **Never store or return a pre-signed URL** (CLAUDE.md §17). Time-limited grants minted per
  request; a stored URL is a reference that works until it silently does not.
- Stream from `ArtifactStore.read`, set `Content-Type` and `Content-Disposition` from the stored
  reference, verify the digest before serving.
- 404 for an artifact belonging to another team — same as one that does not exist, so the endpoint
  is not an oracle for which run ids are real.

### 2b. Report endpoint

`GET /api/v2/test-runs/{runId}/report`

CLAUDE.md §19 lists it. Build it as **JSON**, not HTML — the UI renders it, and a server-rendered
HTML blob is what V1 did (`perf-report.html` at the repo root is the V1 artifact).

Assemble from what is already persisted:

| Piece | Source |
|---|---|
| Run, timings, failure code | `TestRunRepository.find` |
| Objective verdicts | `ResultCatalog.objectiveOutcomesFor` |
| Per-operation metrics | **Not persisted yet — see below** |
| Timeline | `TestRunRepository.events` |
| Artifacts | `ResultCatalog.artifactsFor` |
| Plan digest, engine, shard count | `ExecutionPlanRepository.find` |

**The one real gap:** `NormalizedRunResult` (p50/p90/p95/p99, throughput, error counts per
operation) is computed during analysis and then **thrown away** — only the objective verdicts are
stored. Two options, pick one and say which:

1. **Persist it.** Add a `run_metrics` table in Flyway `V5`, written by
   `RunWorkloadService.analyze`. Fast reads, survives artifact expiry. More schema.
2. **Recompute on read** from the stored `results.jtl` via `engine.parse` + `RunResultReducer`.
   No schema, and it proves the "analysis is re-runnable from stored artifacts" claim — but it
   breaks once artifacts are expired by retention, and it is slow for a large JTL.

Recommendation: **(1)**, with (2) available as a verification path. A report that cannot be read
after artifact retention expires is not a report.

### 2c. Report UI

Add to `platform-ui/src/v2/`:

- `api.ts` — add `getReport(runId)` and `artifactContentUrl(runId, artifactId)`. **All V2 access goes
  through this client** (CLAUDE.md §8); do not scatter axios calls into components.
- New `RunReport.tsx`, rendered from the existing run-detail panel in `PerformanceConsole.tsx`.
- Show: verdict summary, per-operation latency table (p50/p90/p95/p99, throughput, error rate),
  the stage profile, and artifact download links.
- Consumer language only (CLAUDE.md §24) — no thread groups, JMX, samplers or Kubernetes.
  An advanced read-only "generated plan" view is permitted and is where the JMX may be shown.
- **If any chart is added, load the `dataviz` skill first.** Do not hand-roll chart colours.

## 3. After reports — Increment 1E

In order:

1. **Kubernetes execution provider** behind `ExecutionProvider`. Job manifest builder, resource and
   security policy, `backoffLimit: 0`, `activeDeadlineSeconds`, persisted Job UID, observe/cancel.
   **Never auto-replay a failed material run** — that is duplicate load on a real system.
2. **S3-compatible `ArtifactStore`.** The port and key layout already match; the filesystem
   implementation cannot serve multiple replicas.
3. **Runner image with `ConcurrencyThreadGroup`**, so load stages stop being stepwise. Write
   `docs/operations/runner-calibration.md` alongside — shard count is still hardcoded to 1 pending
   calibration.
4. **Housekeeping:** delete `BaselineExecutionPlanCompiler` (dead since `EngineDispatchingPlanCompiler`
   replaced it); add the missing tests listed in `HANDOFF.md` §3a.

Not 1E, but worth knowing the shape of: a scenario's `operationId` has no real path, method, headers
or body until importers land in **Increment 2**. The renderer emits `GET /{operationId}` —
deliberately obvious rather than plausible. Reports built now will look thin for that reason, and
that is honest rather than a defect to hide.
